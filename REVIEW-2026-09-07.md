## Findings addressed in this batch

| Area | Defect and intended correction |
| --- | --- |
| Filter values | Formatted labels were used as query values. Use raw choice codes, numbers, and lookup IDs while keeping readable labels in the picker. |
| Blank filtering | Blank values were included in an `In` list. Use a grouped `Null OR Equal/In` expression. |
| Filter composition | Updating a column discarded nested filters and OR semantics. Preserve unrelated groups and remove only the requested column's conditions. |
| Sorting | Changing dataset sorting can reset its filter. Snapshot and restore the active filter when sorting. |
| Cross-page selection | A synchronous page update could arrive before its waiter was registered. Register before requesting, release failed/cancelled waiters, and restore the starting page. |
| Concurrent paging | Select-all could compete with infinite scrolling and publish partial selection. Mark the scan busy and publish the full selection after restoring the original page. |
| Cell editing and copying | Unsupported values could enter editors and untouched dropdowns could write a default value. Guard supported editors and preserve native copy in text inputs. |
| Cell ranges | Reordered rows could retarget a copied range. Clear the range when rows/columns reorder or disappear, but retain it when pages append. |
| Lookup queries | Special characters could break query URLs and duplicate names could resolve to the wrong record. Encode query values, prefer the actual lookup ID, and reject ambiguous name matches. |
| Infinite scrolling | Rerenders could issue duplicate page requests. Track the loaded page identity and provide recoverable failures. |
| Header alignment | The harness's centred alignment leaked into the header. Explicitly scope alignment to the grid. |
| Development workflow | The file watcher automatically deployed to Dataverse. Make ordinary watch/build loops local and leave deployment explicit. |
| Lint reporting | The PCF lint wrapper could print a failure but exit successfully. Invoke ESLint directly so automation receives the correct exit status. |
| Interactive harness | The Microsoft mock dataset does not apply filter refreshes. Add a separate loopback-only demo using the real grid with 180 sample rows and working mock filtering/paging/editing. |

## Remaining environment checks

Before production use, run a signed-in development-app smoke test:

1. Open a view with more than two pages; scroll, sort, filter, clear filters, and
   refresh. Confirm records are neither duplicated nor retained from an old query.
2. Select records across pages and confirm the host command bar receives the
   intended IDs and the grid returns to its original position.
3. Filter choices, lookups with duplicate display names, and blanks plus a value.
4. Edit permitted scalar/choice/lookup cells and test a read-only or restricted
   column. Confirm rejected writes show an error without changing another field.
5. Navigate away while a lookup request or page load is pending; confirm no stale
   control reappears and no further background paging occurs.

The standard Microsoft PCF harness does not implement full Dataverse metadata,
security, Web API operations, or server-side paging. Its CSV example is useful for
visual checks; `npm run demo` provides interactive mock data, and the automated
tests cover additional failure and timing cases. None replaces the live smoke test.

No Dataverse deployment or package import is part of this batch. Existing
uncommitted repository changes are preserved; publishing them requires an agreed
commit scope. The optional full dependency-advisory scan also requires approval to
send the project's dependency names and versions to npm's advisory service.
